# แผน: ย้ายขั้น "ทำให้ขยับ" ไปรันบน Kaggle (ฟรี)

สถานะ: **ยังไม่เริ่ม** · เขียนเมื่อ 2026-11-17 · ตัวเลขเวลาเป็นค่าประมาณ ต้องวัดจริงในเฟส 1

## ทำไม
LTX 2B บนการ์ดจอ 6 GB ขยับได้แค่เล็กน้อยและหน้าเพี้ยนง่าย โมเดลที่ขยับเป็นธรรมชาติ (Wan 2.2) ต้องการการ์ดจอ 16–24 GB
Kaggle ให้การ์ดจอ 16 GB ฟรี สัปดาห์ละ ~30 ชม. และสั่งงาน/ดึงผลผ่าน API ได้ จึงต่อเข้าระบบอัตโนมัติได้

## ภาพรวมหลังเสร็จ
```
เครื่องนี้ (เหมือนเดิม)                          Kaggle (ใหม่)                          เครื่องนี้
เสียง → วาดภาพ (Animagine) → Gemini เลือกภาพ  ──▶  Wan 2.2 ทำคลิปทีละช็อต (5 วิ, 720p) ──▶  ตรวจหน้าเพี้ยน (CLIP)
      + เขียนคำสั่งขยับเฉพาะช็อต                 จากภาพ + คำสั่งขยับ                      → ตัดต่อ → QC → Telegram
                                                                                       (ช็อตที่พัง/โควตาหมด → LTX ในเครื่อง)
```

## สิ่งที่ต้องเตรียม (เจ้าของทำ ~10 นาที)
1. สมัคร https://www.kaggle.com ด้วย Gmail ของช่อง
2. **ยืนยันเบอร์โทร** (Settings → Phone verification) — Kaggle บังคับก่อนเปิด GPU และอินเทอร์เน็ตในโน้ตบุ๊ก
3. Settings → API → **Create New Token** ได้ไฟล์ `kaggle.json` → วางไว้ที่ Downloads แล้วบอกผู้ดูแล (ระบบย้ายไป `~/.kaggle/kaggle.json` สิทธิ์ 600; เป็นไฟล์ลับ ห้ามแชร์)

## โมเดล
| ตัวเลือก | สัญญาอนุญาต | บน T4 16 GB | ใช้เมื่อไร |
|---|---|---|---|
| **Wan 2.2 TI2V-5B** (`Wan-AI/Wan2.2-TI2V-5B-Diffusers`) | Apache 2.0 | น่าจะได้ด้วย fp16 + CPU offload (Kaggle RAM ~29 GB ช่วย) | **เริ่มที่ตัวนี้** |
| Wan 2.2 I2V-A14B (GGUF Q4) | Apache 2.0 | เสี่ยง/ช้ามาก อาจต้องใช้ T4 สองใบ | ถ้า 5B คุณภาพไม่พอ |

ข้อควรระวัง: T4 และ P100 ไม่มี bf16 ในตัว ต้องรันเป็น fp16 ซึ่งโมเดลบางตัวค่าล้น (ภาพดำ/สัญญาณรบกวน) — ต้องทดสอบในเฟส 1

## ปรับรูปแบบเรื่องให้เข้ากับ Wan
- ช็อตยาวขึ้น จำนวนน้อยลง: ~10–12 ช็อต × ~5–6 วิ ต่อตอน (แทน 18 × 3.5 วิ) — คิวงาน Kaggle ลดลงเกือบครึ่ง และดูเป็นภาพยนตร์ขึ้น
- คำสั่งขยับ (มีแล้วจาก Gemini judge) เขียนเป็นการแสดงจริงได้: "เด็กชายเหวี่ยงไม้ใส่สไลม์ สไลม์กระเด้งถอย กล้องค่อยๆ ซูมเข้า"
- ช็อตยาวกว่าคลิป → เล่นช้าลงเล็กน้อย/ค้างเฟรมท้าย; สั้นกว่า → ตัด

## เฟสงาน (แต่ละเฟสผ่านจุดตรวจก่อนไปต่อ)

**เฟส 1 — ทดสอบด้วยมือ 1 ช็อต (~1 ชม.)**
- เปิดโน้ตบุ๊กใน Kaggle (GPU T4, Internet on) ลง diffusers รุ่นที่รองรับ Wan 2.2 โหลด 5B ทำ 1 ช็อตจากภาพของตอนที่ 1
- วัด: เวลา/คลิป 5 วิ, VRAM, RAM, fp16 ใช้ได้ไหม, คุณภาพเทียบ LTX
- **จุดตรวจ:** เจ้าของดูคลิปเทียบ ถ้าไม่ดีกว่าชัดเจน หรือ >60 นาที/คลิป → หยุดแผน (หรือลอง 480p / A14B)

**เฟส 2 — เก็บโมเดลไว้บน Kaggle (~30 นาที)**
- ดาวน์โหลดน้ำหนัก Wan ครั้งเดียว บันทึกเป็น **Kaggle Dataset ส่วนตัว** แล้วแนบกับโน้ตบุ๊ก — ไม่ต้องโหลด ~20 GB ทุกรอบ
- **จุดตรวจ:** โน้ตบุ๊กเริ่มทำงานได้ภายใน ~3 นาทีโดยไม่โหลดจากอินเทอร์เน็ต

**เฟส 3 — สั่งงานอัตโนมัติจากเครื่องนี้ (~2–3 ชม. เขียนโค้ด)**
- `src/autovideo/story/kaggle.py`:
  1. แพ็กภาพ + คำสั่งขยับ + ความยาวของแต่ละช็อต → อัปเป็นเวอร์ชันใหม่ของ Dataset ส่วนตัว `autovideo-shots` (`kaggle datasets version`)
  2. ส่งโน้ตบุ๊ก `kaggle/animate.py` + `kernel-metadata.json` (GPU on, แนบ dataset ภาพและน้ำหนัก) ด้วย `kaggle kernels push`
  3. เช็กสถานะทุก ~5 นาที (`kaggle kernels status`) — **ไม่บล็อกคิว**: ขั้นนี้คืนสถานะ "รอ" ให้ orchestrator ตั้งเวลาเช็กใหม่ (ใช้ `next_attempt_at` เดิม) งานอื่นในคิวทำต่อได้
  4. เสร็จแล้วดึงคลิป (`kaggle kernels output`) ลง `images/scene_XX.mp4` แล้วตรวจหน้าเพี้ยนด้วย `drift.py` เดิม
- แบ่งช็อตเป็นชุดละ ~6 ช็อตต่อการรัน เพื่อไม่ชนเพดานเวลาของ session บน Kaggle (ประมาณ 12 ชม. ต่อรอบ ต้องเช็กค่าปัจจุบัน)
- **จุดตรวจ:** ตอนที่ 1 ทั้งตอนผ่าน Kaggle อัตโนมัติ ไม่มีคนแตะ

**เฟส 4 — โควตาและทางสำรอง (~1 ชม.)**
- จดเวลา GPU ที่ใช้ต่อสัปดาห์จากผลรัน; ถ้าเหลือไม่พอสำหรับตอนถัดไป หรือ Kaggle ล่ม/ปฏิเสธ → ใช้ LTX ในเครื่องอัตโนมัติ (ระบบปัจจุบัน) และแจ้งใน Telegram
- `/eta` และรายงาน 10 นาที แสดงสถานะ "รอ Kaggle" + โควตาที่เหลือ
- config: `story.animator: kaggle | local`

## ประมาณการ (ต้องวัดจริงในเฟส 1)
- คลิป 5 วิ 720p บน T4: ~20–40 นาที (อาจเร็วขึ้นที่ 480p แล้วขยายด้วย Real-ESRGAN ในเครื่อง)
- ต่อตอน 10–12 ช็อต: ~4–8 ชม. บน Kaggle → 30 ชม./สัปดาห์ ≈ **4–7 ตอนต่อสัปดาห์**
- ระหว่างรอ Kaggle เครื่องนี้ว่าง (วาดภาพตอนถัดไปล่วงหน้าได้)

## ความเสี่ยง
- fp16 บน T4 ใช้ไม่ได้ / ช้าเกิน → ทางออก: 480p, A14B GGUF, หรือกลับไปใช้ LTX
- Kaggle เปลี่ยนโควตา/เงื่อนไข หรือจำกัดงานสร้างวิดีโอ → อ่านเงื่อนไขปัจจุบันก่อนเริ่มเฟส 3
- ต้องใช้เบอร์โทร (ข้อบังคับของ Kaggle)
- คีย์ `kaggle.json` เป็นไฟล์ลับ (อยู่นอกโปรเจกต์ ไม่เข้า git)
